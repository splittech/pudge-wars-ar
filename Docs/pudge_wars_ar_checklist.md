## Как пользоваться документом

- Этапы идут строго по порядку: каждый следующий опирается на результат предыдущего. Этапы 0–3 выполняются целиком в редакторе, без телефона (кроме пробной сборки на этапе 0).
- Каждый пункт `[ ]` — законченное действие, которое можно проверить. Курсив под пунктом — как именно его сделать или на что обратить внимание.
- Этап считается завершённым, только когда выполнены все «Критерии готовности». После этого ставится тег в git.
- Если по ходу работы решение расходится с ТДД, сначала обновите ТДД, затем код.

### Ритуал завершения каждого этапа

- [ ] Все EditMode-тесты зелёные.
- [ ] В консоли нет предупреждений от собственного кода.
- [ ] Все критерии готовности этапа отмечены.
- [ ] ТДД актуален: изменённые решения отражены, в «Историю изменений» добавлена запись.
- [ ] Коммит и тег `vX.Y-название`; короткая заметка «что получилось / что перенесено» в README.

## Этап 1. Ядро и одиночная игра

**Цель:** Вся игровая логика хука и движения — в чистом C# с тестами; в плоском режиме можно ходить и попадать хуком в неподвижного манекена.  
**Длительность:** 2 недели  
**Требования ТДД:** FR-GP-01…08, FR-IN-01…03, FR-IN-06, NFR-04, NFR-05  
**Зависит от:** Этап 0  
**Тег в git:** `v0.1-core`  

### 1.1 Модель данных

- [ ] HeroState (struct): Id, Team, Pos, MoveTarget, Radius, Hp, Alive, IsPulled, HookCooldownEnd.  
  _Только значимые типы и float2 — без ссылок на объекты Unity._
- [ ] HookState (struct): OwnerId, Phase, Origin, Dir, Length, Tip, TargetId, TurnTime, TurnLength, StartTime.  
  _Соответствует HookNetState из раздела 12.4 ТДД плюс серверные поля._
- [ ] Перечисления Team, HookPhase, UpgradeId.
- [ ] События тика (struct): HookThrown, HookHit, HookClash, HeroDamaged, HeroDied.  
  _Пишутся в буфер List\<…>, который переиспользуется между тиками (NFR-01)._
- [ ] Намерения (struct): MoveIntent, ThrowHookIntent, BuyUpgradeIntent; интерфейс IPlayerCommands.

### 1.2 Геометрия

- [ ] Geo2D.CircleCircle для проверки «дотянул до владельца» и клэша.

### 1.3 Логика

- [ ] HeroMovement.Step: движение к MoveTarget со скоростью MoveSpeed, остановка в цели, без движения при IsPulled или !Alive.
- [ ] HookSimulation.TryThrow: проверка готовности и запуск Extending.  
  _Условия — FR-GP-02._
- [ ] HookSimulation.Step — Extending: swept-коллизии с героями, выбор ближайшего попадания по t.
- [ ] Клэш: после шага всех хуков проверить попарно кончики в фазе Extending.  
  _Если два кончика сближаются меньше суммы радиусов — оба в Retracting (FR-GP-07)._
- [ ] Pulling: кончик движется к текущей позиции владельца, цель жёстко на кончике.  
  _FR-GP-08: позиция владельца берётся каждый тик заново._
- [ ] Retracting: пустой кончик возвращается; при достижении владельца — Idle и старт перезарядки.
- [ ] Combat.ApplyHit: урон врагу при входе в Pulling, без урона союзнику, смерть при HP ≤ 0.  
  _Раздел 5.2 ТДД: урон в момент попадания._
- [ ] MatchSimulation.Step в порядке из раздела 11.1 ТДД; очередь намерений.  
  _Намерения применяются в начале тика — это даёт детерминированность._

## Этап 2. Сеть

**Цель:** Та же игра, но сервер считает симуляцию, а два игрока в MPPM видят и поражают друг друга.  
**Длительность:** 2–3 недели  
**Требования ТДД:** FR-NET-01…04, FR-NET-07, FR-UI-01, NFR-03  
**Зависит от:** Этап 1  
**Тег в git:** `v0.2-network`  

### 2.1 NetworkManager и сцены

- [ ] PudgeNetworkManager : NetworkManager, объект в сцене Boot (DontDestroyOnLoad).  
  _Зарегистрировать компонент в RootLifetimeScope через RegisterComponent._
- [ ] Offline Scene = Menu, Online Scene = Match.  
  _Фазы лобби и матча — внутри Match (раздел 12.4 ТДД)._
- [ ] Transport = KcpTransport; sendRate = 30.
- [ ] autoCreatePlayer = false; Player Prefab не задан.  
  _Игроков создаём сами — иначе DI не сработает._

### 2.2 Создание сетевых объектов через DI

- [ ] ScriptableObject NetworkPrefabList и ассет со списком префабов.  
  _На этом этапе: Hero, MatchState._
- [ ] NetworkPrefabFactory (раздел 10.5 ТДД), регистрация в MatchLifetimeScope.
- [ ] OnServerAddPlayer: SpawnServer(heroPrefab, conn) + NetworkServer.AddPlayerForConnection.
- [ ] Проверка: в HeroNet.Construct приходят зависимости и на хосте, и на клиенте.  
  _Временный лог в Construct и в OnStartClient — увидите порядок вызовов._

### 2.3 Серверная симуляция

- [ ] ServerTickRunner (раздел 11.4 ТДД) вместо OfflineSimulationDriver.  
  _Тикает только при NetworkServer.active._
- [ ] IMatchStateSink: после шага переносит позиции в transform.localPosition героев и значения в SyncVar.
- [ ] Регистрация героя в MatchSimulation при спавне и удаление при отключении.

### 2.4 Команды

- [ ] HeroNet реализует IPlayerCommands для локального игрока: MoveTo → CmdMoveTo, ThrowHook → CmdThrowHook.  
  _Реализация регистрируется в контейнере, когда появляется локальный игрок (OnStartLocalPlayer)._
- [ ] Серверная валидация по таблице 12.2 ТДД; команды превращаются в намерения симуляции.
- [ ] Логирование отклонённых команд с причиной.

### 2.5 Синхронизация

- [ ] NetworkTransform (Unreliable) на герое, Coordinate Space = Local.  
  _Сравните позиции на хосте и клиенте при включённых Gizmos — должны совпадать._
- [ ] HP через SyncVar + ReactiveProperty (раздел 11.4 ТДД).
